Introduction

HOBO devices are accelerometer based devices which were originally created for tracking shipping containers across long journeys. Due to their design they are robust to environmental conditions as well as long lasting. The adoption of HOBO devices for animal research allows for tracking of lying and standing time over extended periods (30+ days) with minimal interaction with the animals.

The robo package

The aims of this package are to simplify and standardise the processes of:

  • predicting lying and standing behaviour from HOBO accelerometer data
  • converting behaviour data into bouts
  • summarising behaviour data over time

Tutorial

This tutorial will take us through two example datasets. We will diagnose any problems with the accelerometers and tidy up the data; we will apply a classifier to determine behaviour; and we will process the data into a form suitable for analysis.

To start the tutorial, load the robo package as well as the dplyr package which we will use for data manipulation, the lubridate package for handling times and dates, and the ggplot2 package for visualisation.

library(robo)
library(dplyr)
library(lubridate)
library(ggplot2)
theme_set(theme_bw())

Example One - Cows

Example data has been included in the package to provide examples for this tutorial. Our first example is data collected from cows. Typically on large animals, the HOBO device will be attached with the y-axis aligned along the leg. The z-axis will usually point outwards. Note that this dataset has no x-axis data. Although x-axis data is not needed with this alignment, we recommend exporting it anyway in case you need it for diagnostics.

The example dataset cows is an example of cleaned-up data ready for analysis with robo:

In practice your data will need some processing to make it ready for analysis. In this section we will show the process starting with “raw” CSV (comma-separated value) files through to the analysis-ready cows dataset. If you want to follow this tutorial with your own data, you will need to export CSVs from HOBOware.

Reading HOBO Data

In a typical study you will have data from multiple devices on multiple animals. If the data from each device is exported to a separate CSV in a single directory, you can import these CSVs into R using read_hobo_dir. If you only want to import data from a single device, you can use the read_hobo function.

Use the hobo_example function to find out where R has installed the example CSVs:

cows_path <- hobo_example("cows")
list.files(cows_path)

Diagnostics

Now we need to look at the data that was imported to ensure it is ready for robo to classify. The areas we will check are:

  • Time zones and daylight savings.
  • Deployment time.
  • Orientation, which axis to use, and were they attached the right way around.
  • Sampling frequency.

Accelerometer Traces

Our first diagnostic plot is an accelerometer trace. This can show us whether any of the devices have malfunctioned. If we know when the devices were turned on and off we can check that our time zone conversion was correct. You can open the plot in a new tab for a better view.

ggplot(cows_raw, aes(Time, Y, group=Animal)) +
  geom_line() +
  scale_x_datetime(date_breaks="1 day", date_labels="%b %d") +
  labs(x="", y="y-axis acceleration (g)") +
  facet_wrap(~Animal, ncol=1, strip.position="left")

We can see from these traces that:

  • The data hasn’t been trimmed back to the deployment period.
  • There was something wrong with the device on cow08.

We are going to remove the data for cow08, and we will restrict the rest of the data to the interval April 2 to April 14. Note that we are being careful to specify the time zone since ymd_hms will default to UTC.

cows_clean <- cows_raw |>
  filter_out(Animal == "cow08") |>
  filter(Time >= ymd_hms("2026-04-02 00:00:00", tz="America/New_York")) |>
  filter(Time <= ymd_hms("2026-04-14 23:59:00", tz="America/New_York"))

y-axis Histograms

Because these devices were attached horizontally to the cows, we will use the y-axis to determine standing versus lying. Our second diagnostic plot is a set of y-axis accelerometer histograms. We can use these histograms to check that our thresholds are reasonable. In this case we have used the cut-off described in Ledgerwood 2010 of -0.65g. We have set scales="free_y" in facet_wrap to give each individual histogram its own scale.

ggplot(cows_clean, aes(Y)) +
  geom_histogram(binwidth=0.2, colour="black", fill="white") +
  geom_vline(xintercept=-0.65, linetype="dashed") +
  facet_wrap(~Animal, nrow=2, scales="free_y") +
  labs(x="y-axis acceleration (g)", y="count")

What are we looking for? Standing is to the left (negative values for the y-axis acceleration, i.e. the device is pointing down) and lying is in the middle (small values for the y-acceleration, i.e. the device is lying flat). As a mnemonic, we expect the standing histogram to be tall and narrow (the histogram is “standing up”) and the lying histogram to be more spread out (histogram is “lying down”).

Look closely at the histogram for cow01 - it appears that the device has been attached upside-down, since our cutoff threshold is outside of the histogram range and the “tall” mode is on the right instead of the left. We need to invert the y-axis for this animal. (Technically we want to rotate 180° about the z-axis, which means inverting both the x-axis and the y-axis. However x-axis accelerations were not recorded in this experiment.)

cows_clean <- mutate(cows_clean, Y=if_else(Animal == "cow01", -Y, Y))

Our cleaned data should now match the version of the data supplied with the package:

all.equal(cows, cows_clean, check.attributes=FALSE)

## [1] TRUE

Classifier

Now that we are confident in the quality of our data and our intended threshold, we can use that threshold to classify behaviour. We use the classify_sl (classify standing and lying) function to assign behaviours based on accelerometer readings. We need to specify the axis to use ("Y"), and the threshold to use (-0.65).

cows_bvr <- cows |>
  group_by(Animal) |>
  classify_sl(axis="Y", threshold=-0.65)

sMOOthing

The HOBO data now has a Behaviour column coding observations as either lying or standing. We can perform an additional smoothing step to improve the accuracy of the classification. The smooth_behaviour function goes through the data and gets rid of any short bouts which are often anomalous readings rather than real changes in behaviour Zobel 2015. The bout length for smoothing is controlled by the min_run argument. In the example below, a setting of 2 will smooth out any single bouts, meaning that two consecutive readings are required to agree before we trust a change in classified behaviour. In the example below, the third row is a lying bout in the middle of a long standing bout and is more likely to be noise in the HOBO measurement than a genuine change. The seventh and eighth rows are two consecutive observations coded as lying. These are kept since they are more likely to be a real lying bout.

cows_bvr |>
  ungroup() |>
  slice(12436:12446)

Example Two - Goats

At this point we have finished with the cow data example. In our second example we will look at some goat data.

You can load up the raw goat HOBO data using:

goats_path <- hobo_example("goats")
goats_raw <- read_hobo_dir(goats_path)

goat01 2026-05-01 14:01:00 -1.000 -0.450 -0.125
goat01 2026-05-01 14:02:00 -1.050 0.175 0.025
goat01 2026-05-01 14:03:00 -1.100 0.075 0.025
goat01 2026-05-01 14:04:00 -2.425 -1.625 0.300

Note that all three axes were recorded on these devices.

Accelerometer Trace

First we will look at the data graphically to find any anomalies, in a similar manner to the cow data example. HOBOs are mounted horizontally on goats, so we will be using the x-axis to determine standing and lying.

ggplot(goats_raw, aes(Time, X, group=Animal)) +
  geom_line() +
  scale_x_datetime(date_breaks="1 day") +
  labs(x="", y="x-axis") +
  facet_wrap(~Animal, ncol=1, strip.position="left")

We can see three important things from these traces:

  • The devices have continued to record after being removed at the end of the deployment.
  • There was some sort of problem with goat02 during the middle of the deployment.
  • It looks like the device for goat04 was attached upside-down at the beginning of the deployment, and may also have been removed early.

For this exercise we will remove goat02, remove the early and late data for goat04, and trim the rest of the data to the period 2 to 12 May. We will use a slightly different method to specify days here compared to the cow example, which you may prefer. Note that day(Time) will give the day of the month (rather than the weekday).

goats_clean <- goats_raw |>
  filter_out(Animal == "goat02") |>
  filter_out(Animal == "goat04", day(Time) <= 3) |>
  filter_out(Animal == "goat04", day(Time) >= 12) |>
  filter(day(Time) >= 2) |>
  filter(day(Time) <= 12)

This should now match the clean version of the data supplied with the package:

x-axis Histograms

Because the devices are mounted vertically on legs of the goats, we will look at the x-axis for standing versus lying (rather than the Y for the cows). We tested the -0.45g threshold (dashed line) from Zobel 2015, but based on these histograms that threshold looks to be too high for these goats in these conditions. The threshold should be set to be in the “valley” between the two histogram peaks, and for these goats a -0.60g threshold (dotted line) is more appropriate.

ggplot(goats, aes(X)) +
  geom_histogram(binwidth=0.2, colour="black", fill="white") +
  geom_vline(xintercept=-0.45, linetype="dashed") +
  geom_vline(xintercept=-0.60, linetype="dotted") +
  facet_wrap(~Animal, nrow=3, scales="free_y")

Classifier

We use the classify_sl function again to assign Standing and Lying. We need to specify the axis to use and the value of the threshold (x-axis and a threshold of -0.60 as discussed above). Rather than relying on defaults, we will use the optional arguments here. We will choose a different column name for the classified behaviour ("SL") by setting the name argument. We have kept the default behaviour names "Standing" and "Lying", but we have specified them explicitly here to show how they can be customised. Rather than applying the smoothing after classification, we pass a min_run argument meaning that our "SL" column will already be smoothed (this is easier, but means we don’t have the unsmoothed column available for comparison).

goats_bvr <- goats |>
  group_by(Animal) |>
  classify_sl(axis="X", threshold=-0.60, name="SL", below="Standing", above="Lying", min_run=2)

z-axis Histograms

We can also distinguish left and right lying using the z-axis acceleration. This is not as reliable as lying versus standing, and choosing a threshold can be more difficult. The z-axis is vulnerable to rotation around the leg so we advise using this with caution.

To determine an appropriate threshold, we first remove observations classified as Standing. The remaining observations are used for z-axis histograms. We expect to see a bimodal distribution, usually with a bias towards the animal’s preferred side.

The threshold should roughly separate the two modes, although there us usually substantial overlap. In this case we will use a threshold of -0.65, indicated with dashed lines.

ggplot(filter(goats_bvr, SL=="Lying"), aes(Z)) +
  geom_histogram(binwidth=0.2, colour="black", fill="white") +
  geom_vline(xintercept=-0.60, linetype="dashed") +
  facet_wrap(~Animal, nrow=3, scales="free_y")

Standing, Lying Left, Lying Right

We can perform classification against both axes simultaneously using the classify_slr function. We provide the required arguments (first and second axes and thresholds), as well as an optional name ("SLR") to distinguish this classification result from our previous "SL". We also smooth these results with min_run.

goats_bvr <- goats_bvr |> classify_slr("X", -0.60, "Z", -0.65, name="SLR", min_run=2)

Summaries

Now that we have classified behaviours for our cow and goat examples, we move on to summaries of those behaviours suitable for analysis. This final section of the tutorial will look at daily and hourly summaries of classified behaviour.

Daily Summaries

To get daily summaries we need two functions, group_daily and summarise_time. Calling group_daily adds a Day column to our data and groups by that column, and summarise_time creates the summary based on that grouping (as well as the by-Animal grouping which our data already had).

Note that time="Time" is the default and is not strictly needed here. However, if your time column has a different name, use the time argument to point these functions to the appropriate column.

goats_daily <- goats_bvr |> 
  group_daily(time="Time") |>
  summarise_time(behaviour="SL", time="Time")

goats_daily

goat01 2026-05-02 12.633 11.367 24

goat01 2026-05-04 10.317 13.683 24
goat01 2026-05-05 11.250 12.750 24
goat01 2026-05-06 13.983 10.017 24
goat01 2026-05-07 11.667 12.333 24 
ggplot(goats_daily, aes(Day, 100*Lying/Total)) +
  geom_point() + geom_line() +
  ylim(0,75) + ylab("Lying Time (%)") +
  facet_wrap(~Animal, ncol=3)

Hourly Summaries

We can also summarize the behaviours hourly by using the group_hourly function. By using the default column names "Time" and "Behaviour" we can call group_hourly() and summarise_time without specifying the column names explicitly. Note that group_hourly creates both a "Day" and an "Hour" column.

Make a note here that this is day+hour. If you want time of day, use eg group_by(hour(Time))

cows_hourly <- cows_bvr |>
  group_hourly() |>
  summarise_time()

Bouts

As well as duration measures like total time or percentage of time budget, we might be interested in summarising the frequency and duration of behavioural bouts. To do this we first need to convert our instantaneous samples into bouts using the bouts function.

goats_bouts <- goats_bvr |>
  group_daily() |>
  bouts(behaviour="SL")
